# 0.1.1 主任务状态修复

用户反馈：两个任务进行中时仅显示一个；子任务不需要展示和提醒，只关心主任务。

## 已定位原因

- 菜单栏有待处理任务时以待处理数量替代进行中数量；这两个不同的计数共享一个数字，造成误解。
- 旧的 2 MB 日志尾部窗口可能没有长任务的开始事件。部分 legacy 会话没有历史投影，无法从投影补回状态。
- 启动时把所有未实时连接的历史运行状态置为未知，没有检查该会话是否仍由 Codex 写入。
- 审核类子任务的 source 标明 subagent，但不一定有 parent_thread_id；之前只检查父 ID，导致子任务显示和弹提醒。
- 活动任务也受 24 小时显示过滤限制；现在活动主任务始终保留。

## 修复

菜单栏、侧栏、任务列表和提醒统一使用主任务分类；未确认来源的钩子暂不发提醒。子任务不进入主列表、数量和任何提醒；任务列表也不再提供子任务展开项。主任务按线程 ID 区分，同一项目的两个线程不会合并为一个。

首次读取长日志先检查尾部生命周期；仅缺失可建立当前回合的记录时，按块向前恢复最近的主回合生命周期。数据库旧回合与尾部终态不一致时仍回溯，防止漏掉新回合完成。对子任务 root_turn_id 与 turn_id 不一致的事件不更新主回合状态。读取按行线性切分，避免反复移动整个缓冲区。

已开始且未明确结束的回合，只有对应日志仍有 Codex 可写文件句柄，才能以进程证据恢复长任务运行状态。程序是否存在、CPU 使用率或文件沉默均不能用于推断完成。进程证据不推进日志事件时间，避免较晚写入的完成事件被拒绝。

旧的非活动历史无需每次启动全文扫描：对新发现的主任务查询当前写入句柄（首次数据库不可用时会重试），只对近期、有写入进程或已在增量监控的日志恢复。无可用进程证据仍保留未知，不伪造完成。

## 验证

新增回归包含：两个开始事件位于 2 MB 尾部之外的主任务、跨尾部边界的开始记录、无父 ID 审核任务、未知来源钩子、子任务完成不结束父任务、菜单栏数量、有可写句柄的长任务及完成后不被句柄重新激活。

2026-10-15 最终完整测试 48 项通过，零失败。打包程序实际识别 2 个进行中的主任务，两个均有 Codex 日志写入句柄确认，读取错误为零。原生窗口检查和签名校验通过，旧版已替换并重启。详细结果记于 implementation-progress.md。三入口的等待状态兼容边界仍以 compatibility.md 为准。

补充回归：实时对象格式的 guardian／子代理来源、数据库首次不可用后的旧任务恢复、已完成尾部无需读取大文件前缀、滞后数据库旧回合与新回合终态、终态清除写入进程标记。
