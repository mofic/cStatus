# cStatus Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build a native macOS edge panel that monitors existing local Codex sessions across CLI, VS Code and desktop.

**Architecture:** Read-only session discovery and incremental transcript/history readers feed a deterministic state reducer. A connection to an existing App Server supplies runtime flags; optional official lifecycle hooks supply missing events without modifying official executables. SwiftUI presents snapshots inside AppKit panels.

**Tech Stack:** Swift 5 language mode, SwiftPM, macOS 14+, SwiftUI, AppKit, SQLite3, XCTest; no external packages.

**Spec:** `docs/superpowers/specs/2026-10-15-cstatus-design.md`

## Global Constraints

- Cover CLI, VS Code and desktop as first-class origins; expose gaps rather than claiming unverified full coverage.
- Never infer completion/interruption from silence or start a separate inference server to observe existing tasks.
- Only local processing, read-only Codex database access, no auth-token reads.
- New native app in the supplied directory; Git initialization is blocked by sandbox, so preserve progress in a file.
- User said “执行”: proceed inline through implementation and verification without additional design handoffs.

## Review Focus

- Old turn events arriving after a new turn must not overwrite the new turn.
- Partial writes, rotation, malformed lines and paginated history must not invent states.
- Pending concurrent requests must survive another request being answered.
- First discovery/restart/reconnect must not replay old notifications.
- Missing socket, unsupported version or stale historical active state must never appear as verified live coverage.
