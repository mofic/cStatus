# cStatus：macOS 原生 Codex 状态监控设计

日期：2026-10-15

## 目标与已确认需求

用户同时运行多个 Codex 任务时，无需逐个切换窗口即可发现任务完成、中断，以及需要回答问题或授权的情况。监控范围同时包含本机的 VS Code Codex 插件、Codex 独立客户端和 Codex CLI；三种入口均为核心支持范围。

应用使用 SwiftUI + AppKit，支持屏幕贴边收起、鼠标移入展开和状态变化冒泡提示。按线程标识合并来自不同入口的同一会话，保留入口信息；子任务归入父任务，避免大量子任务提示淹没主任务。

首版以本机任务为范围，不提供跨设备或远程服务器监控。运行在 SSH、容器或远程 VS Code 主机中的 Codex 必须标明尚未接入，不能当作本机完整覆盖。应用只负责监控和定位原客户端，回答问题和批准操作仍在原客户端完成。

## 当前证据与兼容边界

当前工作目录为空，本机具备 Xcode 和 Swift 工具链。本机 CLI 为 0.154.0，已发现的 VS Code 会话包含 0.162.0-alpha.17.2，说明不同入口可能运行不同版本，接入层必须独立处理版本能力。

只读检查本机 `~/.codex/state_5.sqlite`，发现 CLI、VS Code 和子任务来源；抽样会话记录中存在 `task_started`、`task_complete` 和 `turn_aborted`。记录中也存在用户输入工具调用。这些证明了部分发现与事件能力，尚不能证明所有实时状态均持久化。

本机存在 `~/.codex/ipc/ipc.sock`，但其存在不能证明它是可供第三方订阅的 App Server 入口。没有发现标准位置安装的 Codex 独立应用，因此该入口需要可复现事件样本及真实客户端联调，不能以其他入口的测试代替。

官方协议定义了线程状态、回合生命周期、工具事件与服务端请求。协议支持不代表任意已启动客户端都暴露可复用连接；实现前需要验证连接的实例归属、订阅能力和版本。不得启动新的 App Server 后将其会话列表当作其他客户端的实时运行状态。

参考：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。

## 接入方案选择

选择混合方案：本地索引发现会话，现有客户端事件提供实时状态，日志与进程信息补充恢复及异常检测。相比只读日志，能更准确地区分等待与终止；相比所有入口强制使用桥接，减少正常使用时的配置成本。

每个入口都使用可替换的适配器，输出统一事件。优先连接已有实例的受支持状态接口；若无可订阅接口，评估受支持的事件钩子或配套桥接。桥接必须有实证可用的事件来源；不能假设 VS Code 扩展能读取其他扩展内部事件。首版验收前，三种入口均需提供能力表与覆盖证据。

若某入口只能发现会话、无法接收等待事件，UI 显示该能力缺口，不能宣称全状态支持。当前设计以全入口全状态为验收目标，具体接入实现保持证据驱动；若受客户端限制无法达成，需报告实际限制并调整设计，不能悄悄缩减需求。

## 组件与数据流

1. **会话发现器**：读取已识别 Codex 数据目录中的线程索引、会话元数据，并发现可用客户端实例。默认使用 `~/.codex`，支持用户添加其他 Codex 数据目录。数据库以只读方式打开，正确处理 WAL、版本变化、暂时锁定和文件替换。
2. **入口适配器**：分别负责 CLI、VS Code 和独立客户端，发现连接后输出状态快照及增量事件。记录入口版本、连接状态及事件能力。一个适配器失败不阻断其他入口。
3. **事件归一化与状态引擎**：按数据目录和 thread ID 标识会话，按 turn ID 区分回合；维护请求标识、来源、时间及状态可信依据。优先采纳同回合的实时明确事件；过期事件不能覆盖新回合。
4. **状态仓库**：向 SwiftUI 发布任务快照，保存最小必要的本地展示状态和提醒去重标识。日志解析和数据库查询在后台执行，UI 更新回到主线程。
5. **原生窗口控制器**：负责贴边面板、收起把手、鼠标区域、屏幕切换和冒泡窗口。
6. **提醒协调器**：根据有效状态迁移触发提醒、去重和合并；支持点击定位来源。

数据流：发现会话 → 匹配现有实例／读取会话事件 → 归一化事件 → 更新状态引擎 → 更新侧栏与提醒。

本地桥接如确有必要，应只接受当前用户的本地连接，带实例身份与事件能力声明；断线时立即降低覆盖状态。应用不读取认证令牌，不将任务内容发送到外部服务，也不修改官方插件二进制或截取终端输入。

## 状态模型

任务以“当前回合状态 + 活动描述 + 待处理请求集合”表示。思考、工具执行、搜索和压缩等属于运行中的活动描述；若事件源提供，应完整展示。未知的新事件保留类型并进入诊断，不能导致应用崩溃。

| 显示状态 | 判定依据 | 默认提醒 |
| --- | --- | --- |
| 空闲 | 已接入实例明确报告无活动回合 | 无 |
| 运行中 | 明确的回合开始或活动状态；可带当前活动描述 | 无 |
| 等待回答 | 当前回合收到尚未解决的用户输入请求 | 冒泡，保留待处理标记 |
| 等待授权 | 当前回合收到尚未解决的审批请求 | 冒泡，保留待处理标记 |
| 已完成 | 当前回合明确报告成功完成 | 冒泡 |
| 已中断 | 当前回合明确报告中断／取消 | 冒泡 |
| 失败 | 当前回合明确报告失败或终止错误 | 冒泡 |
| 连接丢失 | 已建立的实时连接断开或实例退出，无法确认回合结果 | 冒泡一次，保留最后已知状态 |
| 状态未知 | 无足够证据、版本不支持或历史记录不完整 | 无，卡片显示原因 |

暂停若客户端提供明确事件则展示为“已暂停”；没有事件时不能从无输出推断。重试、网络重连和错误恢复可作为活动描述或连接状态展示，不把可恢复错误直接当作回合失败。

同一回合可以有多个待处理请求。回答／授权必须通过匹配的请求解决事件清除；仍有其他请求时保留等待状态。明确的回合终止事件清空该回合待处理请求。新回合开始后，不得让旧回合的完成或请求事件覆盖新状态。

回合成功完成只表示本轮执行结束，不代表整个项目的目标已完成。长时间没有文件更新只能显示“最近活动时间”，不得判定完成、中断或等待回答。进程退出但没有终止事件时显示连接丢失，不伪造中断。

实时连接断开时保留最后已知任务状态并显示覆盖中断；补读记录可以确认历史完成，但不能掩盖当前实时能力缺失。重新连接后先同步快照，再接收增量事件，避免重复提示。

## 贴边与任务列表交互

默认位于主屏右侧，可切换左侧并拖动设置垂直位置。展开面板约 340 点宽，高度随任务数变化且不超过可用屏幕高度；内容超出时滚动。收起后保留约 12 点宽的把手和简洁状态计数。运行、待处理和失败使用颜色及图标共同区分。

鼠标进入把手约 150 毫秒后展开，离开面板及其冒泡区域约 500 毫秒后收起，避免边缘抖动。提供固定展开按钮；键盘可通过菜单栏入口展开并进入任务列表，不依赖鼠标悬停。

面板使用 AppKit 浮动窗口，展示状态时不抢走键盘焦点；用户主动点击交互区域时才接受必要的键盘操作。不覆盖菜单栏或 Dock，尊重屏幕可用区域。支持外接屏、屏幕移除和缩放变化，屏幕断开后回到主屏。其他 Space 中保持可达，全屏应用场景需实际验证窗口层级与鼠标行为。

任务卡片展示名称、项目、入口、当前状态、最近变化时间及连接覆盖情况。需要处理的任务置顶，其次为失败／中断、运行中和近期完成。支持已处理／隐藏卡片，历史任务不会在启动时全部进入活动列表。

同一 thread ID 的多个入口合并展示入口标签，点击时优先定位最近交互的可用入口。子任务以父任务内摘要展示，用户可展开查看。

## 冒泡与定位

冒泡靠近收起把手显示，默认约 6 秒后消失；鼠标悬停时暂停消失。任务列表中的待处理标记持续到请求解决或用户标记已查看，标记已查看不改变真实任务状态。

去重键包含会话、回合、状态与请求标识。初次启动读取历史快照不发送历史完成提醒；短时间多个事件合并为一组提醒，队列有数量上限。重复事件、重新连接和应用重启均不得造成提醒风暴。运行中的普通活动变化默认仅更新卡片；可在设置中开启额外提示。

点击冒泡或任务卡片，使用实际可验证的 URL scheme、编辑器命令或窗口定位方式打开来源。若不能定位具体线程，至少激活对应客户端并提供项目与线程标识复制入口，明确说明定位程度。不能宣称已跳转到具体任务却只打开了一个新的无关窗口。

系统通知和声音作为可选设置，默认以应用自身冒泡为主。首次用户启用系统通知时才请求通知权限；不为基础监控预先请求辅助功能权限。若某入口确需额外权限才能定位或接入，说明具体用途并保持其他已接入入口可用。

## 设置与诊断

设置包含贴边方向、所在屏幕、固定展开、提醒声音、系统通知和额外 Codex 数据目录。界面采用中文并支持系统深浅色、减少动态效果和 VoiceOver。

诊断页按入口列出：检测到的版本、会话发现是否可用、实时连接是否可用，以及运行／完成／中断／失败／输入／授权等事件覆盖情况。未安装的客户端显示“未检测到”；发现但不支持的版本显示具体缺失能力与原因。

默认诊断只保留事件类型、时间、版本和必要标识，不记录完整提示词、工具参数或代码内容。任务标题仅用于本机展示。对损坏记录、权限不足和不支持版本提供明确错误与重试入口。

## 验证与验收

状态引擎使用去除私人内容的事件样本测试：乱序、重复、新旧回合交错、多个请求、请求解决、失败／中断、重连及未知事件。日志读取验证半行写入、截断、轮转、恢复与数据库暂不可用。

三种入口分别执行运行、正常完成、主动中断、失败、等待回答和等待授权场景。事件源若不支持某场景，需要显示真实缺口；该入口的全状态支持验收不得通过。独立客户端未安装时可以先验证协议样本，但最终必须补充真实客户端联调证据。

同时运行来自不同入口的三个任务，验证各任务状态独立、提醒准确且没有重复；验证同一会话跨入口去重、子任务归属，以及应用重启不重放历史提醒。

对有可靠事件源的入口，目标是在收到本地事件后 1 秒内更新卡片和发出应有冒泡；不把文件写入延迟或未暴露事件包装成实时保证。大体积历史日志采用增量读取，不能每次刷新重新解析全部历史。

在本机验证构建、启动、菜单栏入口、左右贴边、鼠标展开／收起、固定展开、冒泡点击、多个屏幕、睡眠唤醒、Space 和全屏应用。交付可运行的 `.app`、源码、构建说明及逐入口兼容性记录。编译通过不代表上述交互或全状态监控已通过验收。

## 实施顺序与风险处理

先验证各入口的真实状态来源与覆盖能力，再实现统一状态引擎与基础原生面板，随后接入提醒、定位和设置，最后联调与打包。若某入口需要桥接，在验证桥接的事件来源和可用性后再实现，避免先写一个不能获取官方任务状态的空壳扩展。

主要风险为不同入口与版本不共享可订阅状态、等待请求未落盘，以及独立客户端缺少本机测试环境。处理原则是独立适配、明确能力、可复现验证；不能用超时猜测弥补缺失事件。具体文件拆分、测试命令及工作安排由设计批准后的实施计划确定。
