# 兼容性与验证记录

验证环境：2026-10-15，Apple Silicon，macOS 27.0.1，Swift 6.4，应用部署目标 macOS 14。

## 验证原则

三种入口均属于产品目标。下表区分真实本机记录、协议／钩子测试与尚未完成的真实客户端联调。能够解析一条样本不等于能够自动收到某个客户端的全部事件。

| 能力 | 本机真实证据 | 自动化验证 | 当前限制 |
| --- | --- | --- | --- |
| CLI 会话发现 | 本机索引中存在 CLI 和 exec 来源 | 临时数据库与来源映射 | 未启动新的真实 CLI 回合做交互联调 |
| VS Code 会话发现 | 本机有大量 vscode 来源会话 | 数据库、旧日志、协议归一化 | 创建来源不证明当前活跃窗口归属 |
| 独立客户端发现 | 标准应用目录未检测到独立客户端 | desktop 来源映射和统一协议解析 | 缺少安装环境，尚无真实联调证据 |
| 完成／中断／失败 | 历史投影含三类状态，日志含完成和中断事件 | 区分终止状态、乱序和新旧回合隔离 | 历史写入可能有延迟 |
| 等待回答／授权 | 部分会话记录用户输入工具 | runtime flags、服务端请求、钩子元数据、并发请求与解决 | 需要客户端实时服务或可信钩子实际发出事件 |
| 现有服务连接 | 本机默认控制 socket 不存在 | 使用受控进程测试握手、分页、观察和卸载 | `ipc/ipc.sock` 未假定为 App Server socket；服务只代表其中的线程 |
| 钩子桥接 | 未修改用户 Codex 配置 | 原有钩子保留、幂等合并／移除、元数据脱敏、原子文件与解决事件 | 配置后仍需 Codex 审阅信任；不同入口需分别验证 |
| 原生窗口 | 成功创建收起栏、展开栏和冒泡；本机两块屏幕 | Native smoke report 与正／负坐标几何测试 | 尚未人工验证实际鼠标悬停、Space、全屏、睡眠唤醒及拔插屏幕 |

## 已知边界

- 本机目录发现最多 300 条近期非归档主任务记录（先排除子代理，再取限额），并补充历史投影中最新回合未结束的线程；已归档线程不展示。无历史投影时，更早的活跃线程需要实时服务才能补充发现。
- CLI、VS Code 和独立客户端可能各自使用不同版本、不同服务和不同 CODEX_HOME。添加对应目录或配置已有控制 socket，不能靠另一个客户端的空闲服务证明全局空闲。
- 钩子并非完整状态总线。PermissionRequest 在部分版本中没有请求 ID，只能按工具种类匹配后续执行确认；同工具多个并发审批需要实时请求事件才能逐个准确关联。Stop 钩子仅说明输出流结束，不能单凭它判定执行成功。
- 持久化的运行／等待事件在重启时保留为最后已知信息，显示当前状态未确认；实时快照或后续明确事件才能恢复当前状态。
- 点击任务目前激活客户端／项目并复制线程 ID。尚未提供经过真实客户端验证的线程深链，也不自动向终端粘贴执行命令。
- 不监控远程 SSH、容器或云端内部状态；本地看不到的事件不会伪造。
- 本机临时签名可用于当前机器运行；分发签名、公证及 Intel 运行未经验证。

## 交付前仍需补充的真实场景

分别在 CLI、VS Code 和独立客户端执行：启动、完成、主动中断、失败、等待回答、等待授权，以及连接断开／恢复。三入口同时运行至少三个任务，确认每个任务提示准确且不重复。未完成这些证据前，不能将产品标为“全部入口全状态验收通过”。

自动化测试和本机诊断的最新结果记录在 `docs/implementation-progress.md`。
